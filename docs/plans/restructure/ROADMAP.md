# ‏קו ה-restructure (R) — ‏מפת-דרכים

> **‏מה זה**: ‏רצף הסלייסים של המעבר ל-TypeScript מודולרי עם ליבה טהורה,
> ‏ברמת **‏החלטות והיקף** ‏בלבד.
> **‏מה זה לא**: ‏בריף. ‏אין כאן נתיבי-קבצים, ‏חתימות, ‏טבלאות-טסטים ‏או פקודות DoD.
> **‏למה**: ‏אותו רציונל של `docs/plans/sync/ROADMAP.md` — ‏בריף שואב את ערכו מדיוק,
> ‏ודיוק הוא בדיוק מה שנרקב. ‏מפת-דרכים לא נרקבת באותו קצב.
> **‏איך משתמשים**: ‏רגע לפני dispatch ‏כותבים בריף מלא **‏מתוך** ‏הרשומה כאן, ‏ומאמתים אותו אז.
>
> **‏תאריך**: 2026-08-02 · **‏רציונל R0**: `docs/decisions/obsidian-web.md` (‏רשומת 2026-07-31)

## ‏הממצא שקובע את הרצף

**`@ow/core` ‏ניתן לצריכה היום רק ע"י Node.** ‏נמדד ב-2026-08-02:

| ‏מה | ‏הממצא |
|----|-------|
| ‏מה core ‏מייצא | `"exports": { "./fs": "./fs/index.ts" }` — **`.ts` ‏גולמי**. ‏אין שלב emit ‏בשום מקום; `bun run typecheck` ‏הוא `tsc --build` ‏לבדיקה בלבד, ‏והטסטים רצים ‏ב-`node --test "fs/*.test.ts"` (‏type-stripping ‏מקורי של Node). |
| ‏הדפדפן | `build-assets.sh` ‏עושה `cp -r "$MAIN_DIR/src/client-mobile"` — **‏אפס טרנספורמציה**. `index.html` ‏טוען **25 ‏סקריפטים קלאסיים** ‏בסדר ידני, ‏ומעיר בעצמו: *"Classic script (not `type="module"`) — index.html only supports classic scripts here"*. |
| ‏ה-Worker | `_worker.js/` ‏נבנה ‏ב-`cp` ‏של שני קבצים (‏צורת-תיקייה, Pages advanced mode). ‏אין bundling ‏בריפו. |
| ‏צרכני core ‏היום | `grep -rn '@ow/core' src/` → **‏אפס**. |

**‏המסקנה**: R1 ‏מחווט ארבעה אתרים — `sync-server`, `api/fs.js`, `system-plugins.js`,
`api/electron.js` — ‏**‏כולם Node**. ‏הוא יעבור ‏ירוק ‏בלי לגעת בחסם הזה בכלל.
‏הצרכן הראשון שאינו Node ‏ייתקע, ‏וכל הערך של "‏ליבה אחת לכל ה-hosts" ‏תלוי בו.

‏לכן **‏שאלת ה-emit ‏קודמת לכל סלייס-חילוץ שאינו Node** (R2 ‏למטה), ‏ולא נדחית
‏עד שייתקעו בה.

## ‏החלטות חוצות-סלייסים (‏סגורות)

1. **‏הליבה טהורה**: `packages/core` — TS, ‏אפס תלויות-ריצה, ‏אפס IO, ‏אפס מקורות-זמן.
   ‏הגבול נאכף ‏ע"י `scripts/check-core-boundary.mjs` (R0), ‏לא ‏ע"י משמעת.
2. **‏אפס שינוי התנהגות** ‏בכל סלייס-חילוץ — ‏כולל גוף-שגיאה, ‏קוד-שגיאה ‏וצורת-החוט.
   ‏זו דרישה מחייבת, ‏לא שאיפה. ‏ארבעה סבבי אימות ב-R1 ‏מצאו כאן רגרסיות שקטות
   ‏שאף טסט קיים לא תפס.
3. **‏חילוץ לפני המרה**: ‏קודם מזיזים לוגיקה **‏כפולה** ‏לליבה (‏שם הרווח מיידי ומדיד),
   ‏ורק אחר כך ממירים קבצים שלמים ל-TS. ‏המרה סיטונאית ‏של 10,000 ‏שורות JS ‏אינה ברצף.
4. **‏שער-רגרסיה לפני החיווט, ‏לא אחריו** (R1 Commit 0). ‏שער שנכתב אחרי השינוי
   ‏לא מוכיח דבר.
5. **legacy ‏לא נכנס לליבה** — `src/sync-server` ‏ו-`src/client-mobile/sync` ‏נשארים
   ‏כפי שהם (‏החלטה 9 ‏ב-`docs/plans/sync/ROADMAP.md`). ‏חילוץ מהם הוא עבודה מבוזבזת.
6. **`src/` ‏לא זז ל-`packages/`** ‏באף סלייס ברצף הזה. ‏זו החלטה נפרדת שלא נדונה.

## ‏הרצף

### R0 — `monorepo-foundation` ✅ ‏בוצע, ‏ממתין למיזוג
**‏מה נתן**: workspaces ‏עם bun · `packages/core` ‏עם tsconfig project-references ·
‏סקריפט-גבול נאכף · `toRelative` ‏על 7 ‏טסטים ‏כהוכחת-צינור · `bunfig.toml` ‏שמציל
‏את מסלול ה-npm.
**‏מצב**: 9 ‏סבבי אביגיל (71 ‏ממצאים) → READY. ‏בוצע ב-`slice/r0-qwen`, 4 ‏קומיטים,
‏אפס נגיעה ב-`src/`. **‏ממתין ל-כלב ‏ולמיזוג ל-dev.**

### R1 — `core-resolve-safe` 🟡 ‏בריף טיוטה, ‏לא מאומת
**‏מטרה**: `resolveSafe` — ‏שומר ה-path-traversal — ‏קיים ‏ב**‏ארבעה** ‏מימושים לא-זהים
‏בשתי חבילות. ‏אחרי הסלייס יש **‏אחד**, ‏ב-`@ow/core`, ‏עם טסטים.
**‏בחוץ**: ‏כתיבת `toRelative` ‏מחדש (‏מגיעה מ-R0) · ‏העברת חבילות ל-`packages/`.
**‏תלוי ב**: R0 ‏מוזג.
**‏מצב**: ‏4 ‏סבבי אביגיל, ‏ובכל אחד **‏התיקון ייצר רגרסיה חדשה** — *"‏התיקון סוגר את
‏השדה שנבדק ומשאיר את השדה שלידו"*. ‏הבריף הנוכחי ‏**‏לא עבר אימות בצורתו הזו**.
**‏למה הוא ראשון**: ‏ארבעת האתרים נבדלים זה מזה ב-7 ‏ממדים נמדדים (§3 ‏בבריף) —
‏זהו המקרה הקשה, ‏והוא גם היחיד שהוא **‏גבול-אבטחה**.
**‏מגבלה שצריך לומר בקול**: ‏כל ארבעת האתרים הם Node. **R1 ‏לא מוכיח שהליבה
‏חוצה runtime.**

### R2 — ‏שלב-בנייה ל-`client-mobile` ✅ **‏הוכרע 2026-08-02**
**‏ההחלטה**: **Vite 8 ‏עם Rolldown**, ‏שרת-הפיתוח ‏**‏כבוי**, `vite build --watch` ‏בלבד.
`src/runtime-server/server` ‏ממשיך להגיש את הקבצים ואת `/api/*` ‏כמו היום — ‏אין שרת
‏שני, ‏אין proxy, ‏אין הבדל בין dev ‏לפרודקשן. HMR ‏לא בשימוש ‏(‏הוא ממילא חסר-משמעות
‏כאן: ‏המודולים מתקינים `window.require` ‏וגלובלים ‏**‏לפני** ‏שהחבילה של Obsidian נטענת).

**‏נמדד ‏בפועל** (`/tmp/vite-bun-probe`, Vite 8.2.0):

| ‏מה נבדק | ‏תוצאה |
|---------|-------|
| `bun run vite build` (‏מריץ ‏תחת Node) | ✅ exit 0. `vite/8.2.0 linux-x64 node-v25.9.0` |
| `bun --bun run vite build` (‏תחת ‏ריצת Bun) | ✅ exit 0, `bun-v24.3.0`, **‏פלט זהה byte-for-byte** ‏ל-Node |
| `vite build --watch` | ✅ ‏בנייה-מחדש ‏ב-13ms; ‏ה-hash ‏בשם-הקובץ ‏משתנה |
| ‏ריבוי נקודות-כניסה | ✅ `build.rolldownOptions.input` |
| ‏פלט **‏סקריפט קלאסי** (IIFE) | ✅ `var __owCore=(function(e){…})({})` |

**‏המסקנה המבצעית ‏החשובה ‏ביותר** — ‏פלט ה-IIFE: ‏מודול TS ‏מקומפל ‏לסקריפט **‏קלאסי**
‏שנתלה על גלובל, ‏כלומר **‏בדיוק ‏החוזה ‏הקיים ‏של `window.__ow*`**. ‏לכן R4 ‏יכול להמיר
‏מודולים ‏ל-TS ‏**‏בלי לגעת ‏ב-`index.html` ‏בכלל** ‏בשלב הראשון — ‏המעבר ל-`type="module"`
‏הוא צעד נפרד ‏ומאוחר, ‏לא תנאי-כניסה.

**bun**: ‏נשאר ‏מנהל-החבילות ‏ומריץ-המשימות (‏כפי ש-R0 ‏קבע). ‏Vite ‏עצמו ‏ירוץ ‏**‏תחת Node** —
‏כלומר `bun run vite build`, ‏**‏לא** `bun --bun`. ‏זאת ‏למרות ‏ששתיהן ‏עברו ‏במדידה:
VoidZero ‏הצהירו ‏ש-Bun ‏**‏כ-runtime** ‏אינו ‏יעד ‏נתמך (‏כמנהל-חבילות ‏— ‏כן), ‏ויש ‏באג
‏פתוח ‏שבו `undefined` ‏ב-`define` ‏נופל ‏על ‏napi ‏מחמיר ‏של Bun (oven-sh/bun#26388).
‏אין ‏סיבה ‏לקחת ‏סיכון ‏על ‏נתיב ‏לא-נתמך ‏עבור ‏אפס ‏רווח ‏מדיד.

**‏מה ‏שנשאר ‏פתוח ‏ל-R2**: ‏מי ‏הבעלים ‏של `index.html`. ‏ההמלצה — ‏**‏אנחנו**, ‏לפחות ‏עד ‏סוף R5:
Vite ‏פולט ‏צרורות ‏בשמות ‏קבועים ‏וה-HTML ‏נשאר ‏כתוב ‏ביד ‏עם ‏ההערות ‏שלו, ‏שהן ‏תיעוד
‏נושא-משקל ‏שנכתב ‏לאורך ‏כמה ‏סלייסים ‏מאומתים.

**🔴 ‏מכשול ‏לרישום**: Vite 8 ‏דורש **Node 20.19+ / 22.12+**. ‏הפרויקט ‏מצהיר ‏היום
"Node 18+ or Bun" ‏ב-`README.md` ‏וב-`AGENTS.md`. ‏רצפת ה**‏ריצה** ‏של ‏השרת ‏יכולה
‏להישאר 18; ‏נוצרת ‏רצפת **‏בנייה** ‏נפרדת ‏וגבוהה ‏יותר. ‏חייב ‏להיאמר ‏במפורש —
‏הבריף ‏של R0 ‏כבר ‏סימן ‏"‏רצפת Node" ‏כסיכון ‏ודחה ‏בכוונה ‏נגיעה ‏ב-README.

### R3 — ‏רשימת-ההיתר של הפרוקסי ‏לליבה
**‏מטרה**: `isAllowed` ‏קיים ‏בשני עותקים — `src/runtime-server/server/api/proxy.js`
(Node, CJS) ‏ו-`src/deployments/cloudflare/proxy-worker.js` (Worker, ESM). ‏אחרי
‏הסלייס יש אחד.
**‏למה הוא הבא**: ‏זהו **‏גבול-SSRF**, ‏הוא טהור לחלוטין (`URL` ‏ומחרוזות בלבד),
‏והוא **‏הצרכן הראשון של הליבה שאינו Node** — ‏כלומר הוא המקום שבו החלטת R2
‏נבחנת בפועל, ‏בקוד קטן ‏שקל לגבות.
**‏הסתייגות ‏שנרשמה 2026-08-02**: ‏ה-Worker ‏**‏אינו host ‏של ‏האפליקציה** — ‏הפריסה
‏ב-Cloudflare ‏היא client-only (OPFS), ‏וה-Worker ‏קיים ‏אך ‏ורק ‏עבור `/api/proxy-request`
(‏פרוקסי-CORS ‏להתקנת ‏פלאגינים), 337 ‏שורות ‏בסך ‏הכל. ‏לכן ‏הסלייס ‏הזה ‏הוא ‏**‏קטן
‏ומבחני**, ‏לא ‏אבן-דרך ‏ארכיטקטונית. ‏אם ‏מסתבך — ‏לגיטימי ‏להשאיר ‏את ‏השכפול ‏ולהמשיך ‏ל-R4.
**‏נמדד**: ‏שני העותקים ‏**‏עדיין זהים פונקציונלית** (‏ההבדל היחיד הוא הערות ‏ורשומה
‏כפולה של `raw.githubusercontent.com` ‏בעותק ‏ה-Node — ‏חסרת-השפעה, `Set`).
‏כלומר **‏עוד לא נסחפו** — ‏זה הזמן לאחד, ‏לפני שהם נסחפים כמו `resolveSafe`.
**‏תלוי ב**: R2 (‏מסלול ‏א' ‏או ב'). ‏במסלול ‏ג' — ‏הסלייס יורד.

### R4 — ‏המודולים הטהורים שכבר קיימים, ‏לתוך הליבה
**‏מטרה**: ‏בריפו כבר קיים דפוס "‏מודול טהור" — ‏קבצים שנכתבו ‏כ-IIFE ‏שנתלית
‏על `window.__ow*` ‏כדי שיהיו ‏גם ‏ניתנים-לטעינה ‏ב-`node:test` ‏וגם ‏ב-`<script>`.
‏זה מודול-סיסטם ידני. R0 ‏נתן ‏מודול-סיסטם אמיתי; ‏כאן ממירים.
**‏מועמדים נמדדים** (‏אפס עד שתי הפניות חיצוניות כל אחד):
`sync/decide-pull.js` (75, ‏אפס) · `shims/path.js` (120, ‏אפס) ·
`vault-root-path.js` (43) · `bootstrap-lookup.js` (61) · `cache-invalidation.js` (67).
**‏הרווח האמיתי**: ‏לא השורות — ‏אלא ‏מחיקת ‏שורות מסדר-הטעינה ‏ב-`index.html`,
‏שהוא היום גרף-תלויות ‏מתוחזק-ביד ‏עם 25 ‏צמתים ‏והערות ‏מסוג "‏חייב להיטען לפני boot.js".
**‏בחוץ**: `sync/decide-pull.js` ‏אם קו-הסנכרון ‏כבר החליף אותו (‏החלטה 5).
**‏תלוי ב**: R2 + R3.

### R5 — ‏חילוץ החלטות מתוך שלושת הקבצים הגדולים

**‏למה לא קודם**: ‏אין כאן שכפול-מדיד ‏שמצדיק ‏את הסיכון, ‏והם קוד-ריצה חי ‏ללא
‏שער-רגרסיה משמעותי. ‏זה הסלייס שהכי קל לשבור בו את המוצר בשקט.
**‏תלוי ב**: R4 (‏הדפוס מוכח בקטן) · ‏שער-רגרסיה ‏בדפדפן ‏שעדיין לא קיים.
